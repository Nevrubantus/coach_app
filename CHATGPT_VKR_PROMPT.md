Общее описание проекта:

Разработана информационная система Progress Fit для учета, анализа и отслеживания прогресса спортивных тренировок. Система предназначена для двух основных ролей: спортсмена и тренера.

Спортсмен может:

- зарегистрироваться и войти в аккаунт;
- при регистрации подтвердить согласие на обработку персональных данных;
- вести профиль: имя, телефон или email, рост, вес, возраст, фото;
- редактировать фото профиля: увеличивать, уменьшать и смещать фото внутри круглого аватара;
- видеть своего закрепленного тренера с фото, именем и контактом;
- создавать тренировки на выбранную дату и время;
- выбирать упражнения из библиотеки;
- добавлять упражнения в тренировку;
- заполнять подходы: рабочий вес, повторения, заметки;
- прикреплять видео к каждому подходу;
- открывать загруженные видео;
- видеть комментарии тренера к видео;
- смотреть график прогресса рабочего веса по упражнениям;
- смотреть график изменения собственного веса;
- пользоваться приложением в светлой и темной теме.

Тренер может:

- зарегистрироваться и войти как тренер;
- редактировать свой профиль и фото;
- закреплять спортсменов за собой по телефону или email;
- видеть список закрепленных спортсменов с их фото;
- открыть спортсмена и посмотреть его предстоящие и прошедшие тренировки;
- назначить спортсмену новую тренировку;
- редактировать предстоящую тренировку спортсмена;
- открыть прошедшую тренировку спортсмена;
- смотреть видео подходов спортсмена;
- оставлять комментарии к видео;
- видеть динамику рабочего веса и веса тела спортсмена;
- вести собственные личные тренировки как обычный пользователь системы.

Администратор:

Отдельный мобильный интерфейс администратора не реализован. Администратор работает через серверную консоль `coach_app_server/bin/admin.dart`. Это сделано для дипломного прототипа, чтобы не перегружать приложение третьим интерфейсом.

Администратор может:

- посмотреть пользователей;
- посмотреть связи тренер-спортсмен;
- назначить пользователю роль тренера или спортсмена;
- вручную привязать спортсмена к тренеру;
- отвязать спортсмена от тренера;
- управлять библиотекой упражнений: добавлять упражнение, менять описание, добавлять фото, удалять упражнение.

Архитектура:

Система состоит из трех основных частей:

1. Flutter-клиент.
2. Serverpod-сервер.
3. PostgreSQL база данных.

Дополнительно используется:

- Redis как вспомогательный сервис Serverpod;
- Docker для контейнеризации базы, Redis и серверной части;
- Nginx как reverse proxy на VPS;
- GitHub для хранения кода и обновления сервера;
- Cloudflare для подключения домена `progress-fit.ru`;
- Beget VPS как текущий серверный вариант развертывания.

Клиентская часть:

Flutter используется потому, что позволяет из одной кодовой базы запускать приложение на Android, Windows и в браузере как Flutter Web. Основная пользовательская логика находится в `coach_app_flutter/lib`.

Серверная часть:

Serverpod используется как backend-фреймворк на Dart. Он выбран потому, что хорошо связан с Flutter, умеет генерировать клиентский протокол, поддерживает PostgreSQL, миграции и endpoint-методы.

Основные серверные файлы:

- `coach_app_server/bin/main.dart` - точка входа сервера;
- `coach_app_server/bin/admin.dart` - консоль администратора;
- `coach_app_server/lib/server.dart` - создание Serverpod-сервера и подключение endpoints;
- `coach_app_server/lib/src/users/user_endpoint.dart` - регистрация, вход, профиль, фото профиля, хэширование пароля;
- `coach_app_server/lib/src/coaches/coach_endpoint.dart` - закрепление спортсменов за тренером, получение списка спортсменов и данных тренера;
- `coach_app_server/lib/src/training/training_endpoint.dart` - тренировки, упражнения, подходы, видео, комментарии, графики;
- `coach_app_server/lib/src/training/workout_delete_helper.dart` - корректное удаление тренировки со связанными данными;
- `coach_app_server/lib/src/web/routes/app_config_route.dart` - выдача конфигурации для web-клиента;
- `coach_app_server/lib/src/web/routes/root.dart` - web-route Serverpod.

База данных:

Используется PostgreSQL. Данные хранятся в связанных таблицах.

Основные сущности:

- `app_user` - пользователи: имя, контакт, хэш пароля, роль, рост, вес, возраст, фото, параметры кадра фото;
- `coach_athlete` - связь тренера и спортсмена;
- `exercise` - библиотека упражнений;
- `workout` - тренировка;
- `workout_exercise` - упражнение внутри тренировки;
- `workout_set` - подход упражнения;
- `workout_video` - видео, прикрепленное к подходу;
- `video_comment` - комментарий тренера к видео;
- `body_weight_entry` - история веса тела пользователя;
- `progress_point` - модель точки графика.

Файлы видео и фото:

Видео и изображения не хранятся прямо в PostgreSQL. В базе хранится путь к файлу, а сам файл лежит на сервере.

Примеры:

- видео подходов: `web/static/uploads/videos`;
- аватары профиля: `web/static/uploads/avatars`;
- фото упражнений администратора: `web/static/uploads/exercises`.

На VPS папка uploads подключается как volume:

`/opt/coach_app/uploads:/web/static/uploads`

Это нужно, чтобы файлы не пропадали при перезапуске Docker-контейнера.

Открытие видео:

Видео открывается как обычный статический файл, например:

`http://progress-fit.ru/uploads/videos/set_video_....mov`

Важно: видео не открывается через `/serverpod/uploads/...`, потому что `/serverpod/` зарезервирован для API endpoints. Если открыть видео через `/serverpod/uploads/...`, Serverpod будет искать endpoint и выдаст ошибку `Endpoint not found`.

Протокол:

Serverpod генерирует клиентский протокол в `coach_app_client`. Это набор Dart-классов и методов, которые позволяют Flutter-приложению вызывать серверные методы как обычные функции:

`client.training.listWorkouts(userId)`

Серверный endpoint принимает запрос, работает с базой и возвращает результат. Flutter напрямую не пишет SQL-запросы.

Миграции:

Миграции базы данных находятся в `coach_app_server/migrations`. Они фиксируют историю изменений структуры БД. Когда добавляются новые таблицы или поля, Serverpod создает новую миграцию. При запуске с `--apply-migrations` сервер применяет недостающие миграции к PostgreSQL.

Информационная безопасность:

В проекте реализована базовая защита:

- пароль не хранится в открытом виде;
- сервер сохраняет SHA-256 хэш пароля с демо-солью;
- при регистрации пользователь обязан отметить согласие на обработку персональных данных;
- роли хранятся на сервере;
- тренер может работать только с закрепленными спортсменами;
- загрузка фото и видео идет через серверные методы;
- для реального продукта нужно заменить SHA-256 на bcrypt, Argon2 или PBKDF2 с уникальной солью для каждого пользователя.

Офлайн-режим:

Приложение не является полноценной offline-first системой. Но оно сохраняет последние данные в локальный кэш. Если сервер временно недоступен, пользователь видит сохраненные данные, а не пустой экран. Это важно для демонстрации устойчивости интерфейса.

Темная тема:

Добавлена светлая и темная тема. Выбор хранится в SharedPreferences. В профиле есть переключатель в виде прямоугольника, разделенного на две части: слева солнце, справа полумесяц. При выборе нужная часть выделяется внутренней рамкой. Общие карточки и поля используют цвета из `app_theme.dart`, поэтому интерфейс адаптируется к теме.

Развертывание:

Текущий быстрый серверный вариант:

- VPS Beget;
- IP: `212.8.228.9`;

Схема Nginx:

- `/serverpod/` проксируется на `127.0.0.1:8080`;
- `/app/`, `/uploads/...` и остальные web-запросы проксируются на `127.0.0.1:8082`.

Команда обновления на сервере:

`cd /opt/coach_app && git pull && bash deploy_beget.sh`

Cloudflare:

Домен подключается через Cloudflare. В быстром варианте можно использовать SSL-режим Flexible, потому что на origin-сервере работает обычный HTTP. Для промышленной версии лучше настроить HTTPS-сертификат на сервере и использовать Cloudflare Full или Full strict.

Ограничения прототипа:

- это демонстрационная система, не промышленный продукт;
- хэширование пароля базовое, для реальной системы нужен более сильный алгоритм;
- офлайн-режим только показывает сохраненные данные, но не синхронизирует изменения в обе стороны;
- файлы хранятся на сервере, а не в отдельном объектном хранилище;
- администраторский интерфейс реализован через консоль, а не через отдельную web-панель;
- Serverpod Auth не используется, вход реализован через собственный `UserEndpoint`.
